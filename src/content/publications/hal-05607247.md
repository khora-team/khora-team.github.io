<div><p>LLMs are becoming increasingly effective in software evolution tasks such as automated program repair, refactoring, API misuse fixing, and code migration. These advances can substantially reduce the manual effort required for maintaining, refactoring, and evolving complex software systems. However, code generated by LLMs often suffers from limited explainability and a lack of determinism due to their black-box nature. Their usage cost can also rise, particularly when applied to large code bases with repetitive tasks. Code transformation rules mitigate those challenges by providing a high degree of explainability, determinism, and reuse on large code bases. Hence, an opportunity is to leverage LLMs to generate the code transformation rules rather than directly updating the code. Yet, to the best of our knowledge, there is a lack of literature on LLM's ability to formalize and generate code transformation rules.</p><p>This paper fills this gap. We present a novel empirical study on the ability of LLMs to generate code transformation rules. Instead of focusing solely on direct code generation, we investigate whether LLMs can produce explicit and reusable transformation rules expressed in three domain-specific languages (DSLs), namely Comby, GritQL, and Ast-Grep. We evaluate three LLMs (GPT-5.4, GPT-oss-120B, and Llama3.1-8B) on six diverse datasets covering four software-evolution tasks: API misuse correction, program repair, API migration, and language version migration. We analyze how such rules can be derived from code changes and evaluate their syntactic validity, structural completeness, generalization capacity, and transformation correctness. We complement this quantitative evaluation with a qualitative analysis of success and failure modes.</p><p>Our results provide evidence that transformation rule synthesis moves beyond proof-of-concept with strong frontier models.
